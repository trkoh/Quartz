# API Gatewayの種類

API タイプとして以下の種類がある

- HTTP API
- WebSocket API
- REST API
- REST API プライベート

# [用語](https://docs.aws.amazon.com/ja_jp/apigateway/latest/developerguide/api-gateway-basic-concept.html)

### API デプロイ

APIを公開するためには、デプロイという操作が必要。

デプロイの際は、必ず一つのステージを指定してデプロイが必要。


### API ステージ

デプロイ内容は、ステージごとに履歴を保持する。

- 例:
	- ステージごとにアクセスURLが異なる
		- prod ステージ: https://<api-id>.execute-api.<region-id>.amazonaws.com/prod/...
		- staging ステージ: https://<api-id>.execute-api.<region-id>.amazonaws.com/staging/...
		- dev ステージ: https://<api-id>.execute-api.<region-id>.amazonaws.com/dev/...
	- prodステージへのデプロイで問題が起こった場合、prodステージ内のデプロイ履歴をもとにロールバック可能

# REST API

### リソース設定

URLパスの一部(/users、など)を指す。

APIを作成すると、最上位に "/" で表現されるリソースが作成される。

その下に入れ子で複数のリソースを作成可能。

各リソースにはメソッドを複数構成可能。

例:
```
REST API
│
├── / (ルートリソース)
│   │
│   ├── /users (リソース)
│   │   ├── GET     → Lambda: listUsers
│   │   ├── POST    → Lambda: createUser
│   │   │
│   │   └── /{userId} (パスパラメータ付きリソース)
│   │       ├── GET    → Lambda: getUser
│   │       ├── PUT    → Lambda: updateUser
│   │       └── DELETE → Lambda: deleteUser
```

### メソッド設定

リソースとメソッドの組み合わせごとに、以下の4つの設定を行う

- メソッドリクエスト
- 統合リクエスト
- 統合レスポンス
- メソッドレスポンス
