# HTTPS 化に必要な作業

## 前提:

HTTPSは「HTTP Secure」の略で、HTTPにSSL/TLSと呼ばれる暗号化技術を組み合わせた通信方式のこと。

SSL/TLS 通信は2つのフェーズに分かれる（参考: [SSL通信の仕組み](getting_started_with_ssl_and_https.md#^2dc214)）
- 前半: ハンドシェイク（公開鍵暗号方式で共通鍵を交換）
- 後半: データ転送（共有鍵暗号方式で通信を暗号化）

ハンドシェイクとは、のちのデータ転送で使用する共有鍵を確立するため、[公開鍵暗号方式](getting_started_with_ssl_and_https.md#^fb052e)で準備動作を行うフェーズのこと。

公開鍵暗号方式は以下のイメージ
```
### 1. 鍵ペアの生成
Server
  |
  | 鍵ペア生成
  |
  ├── 公開鍵 (Public Key)  ← 誰でも知ることができる
  └── 秘密鍵 (Private Key) ← サーバーだけが保持


### 2. 公開鍵の配布
Client                    Server
  |                         |
  |   公開鍵を要求           |
  |------------------------>|
  |                         |
  |   公開鍵を送信           |
  |<------------------------|
  |                         |


### 3. 暗号化通信
Client                    Server
  |                         |
  | 平文を公開鍵で暗号化      |
  |------------------------>|
  |      暗号文送信         |
  |                         |
  |                    秘密鍵で復号化
  |                    → 平文を取得
```

つまり、HTTPS 通信(SSL/TLS通信)のためには事前にサーバー側で**公開鍵、秘密鍵**の準備が必要。

また、クライアントは安全のために**信頼できる**公開鍵を使う必要がある。

ここで登場するのが、**サーバー証明書**

HTTPSにおける証明書とは、「公開鍵」が「被証明者のもの」であることを証明する。

そして、公開鍵の正当性を保証する存在が必要。

これが、**CA(Certification Authority: 認証局)**

サーバーは、証明書の作成にあたってCAに公開鍵の正当性の保証を依頼する。


## 作業の流れ

HTTPS化にあたって、サーバー側で以下の作業が必要となる。

- **秘密鍵の生成**
- **CSR(証明書署名要求)の作成**
- **CAに証明書発行依頼**
- **証明書の受け取り**
- **アプリケーションに証明書を設定**
- （定期的に）証明書の有効期限の更新

また、サーバー側で以下のファイルを作成することになる

- `xxx.key`: 秘密鍵
- `yyy.csr`: 証明書署名要求（一時的）
- `zzz.crt`: サーバー証明書
	- サーバーの公開鍵 と CAによる署名 が含まれる

# やってみる
## 秘密鍵の作成

```
$ sudo su

// 2048 bit の鍵長でRSA秘密鍵を作成
$ openssl genrsa 2048 > /etc/httpd/conf/server.key
```

```
// 中身を確認
$ openssl rsa -text < /etc/httpd/conf/server.key
Private-Key: (2048 bit, 2 primes)
modulus:
    00:b...
publicExponent: xxxxx (0x10001)
privateExponent:
    01:d...
prime1:
    00:f...
prime2:
    00:b...
exponent1:
    60:6...
exponent2:
    00:8...
coefficient:
    00:8...
writing RSA key
-----BEGIN PRIVATE KEY-----
...
-----END PRIVATE KEY-----
```
秘密鍵の内容は以下。このテキストをPEM形式と呼ぶ
- `modulus`
	- 秘密鍵で用いる2つの素数の積（N=PQ）
	- 16進数表記を2桁ずつ`:`で区切ってある
	- この情報は公開鍵およびCSRにも含まれる
- `prime1`, `prime2`
	- 2つの素数（P / Q）に相当
	- 16進法表記
- `publicExponent`
	- RSA 構造体のEに相当
- `privateExponent`
	- RSA 構造体のDに相当
- `exponent1`, `exponent2`
	- RSA構造体の dmp1(D mod (P-1)) / dmq1(D mod (Q-1))に相当
- `cofficient`
	- RSA構造体のiqmp ((Q-1) mod P)に相当
- `-----BEGIN PRIVATE KEY-----` ~ `-----END PRIVATE KEY-----`
	- 実際の秘密鍵の内容

## CSR の作成

作成した秘密鍵を使用して CSR を作成する。

CSR 作成時、下記の項目について対話形式で聞かれる。

認証局はこれらの情報をもとに証明書の正当性を判断するため、実情に沿って正しい情報を記入する必要がある。（自己証明書の場合は何でもいい）

- `Country Name(2 letter code)`
	- 例: `JP`
- `State or Province Name(full name)`
	- 例: `Tokyo`
- `Locality Name(eg, city)`
	- 例: `Chuo-ku（市町村名）`
- `Organization Name(eg, company)`
	- 例: `test corp.`
	- ※ Common Name に入力したドメインで whois した際に取得できる企業名、など
- `Organizational Unit Name(eg, section)`
	- 例: `eg, section（部署名など）`
- `Common Name(eg, your name or your server's hostname)`
	- 例: `xxxx.dev（SSL/TLSを導入するドメイン名）`
- `Email Address`
	- 例: `test@example.com（サーバー管理者のメールアドレス）`

- extra attributes（指定しなくても良い）
	- `A challenge password`: 秘密鍵に対するパスワード
		- 指定すると、秘密鍵へのアクセス毎にパスワードが求められる
	- `An optional company name`

```
// 秘密鍵を指定(-key)し、新たに(-new) CSR ファイルを作成する
$ openssl req -new -key /etc/httpd/conf/server.key > /etc/httpd/conf/server.csr
You are about to be asked to enter information that will be incorporated
into your certificate request.
What you are about to enter is what is called a Distinguished Name or a DN.
There are quite a few fields but you can leave some blank
For some fields there will be a default value,
If you enter '.', the field will be left blank.
-----
Country Name (2 letter code) [XX]:JP
State or Province Name (full name) []:Tokyo
Locality Name (eg, city) [Default City]:Chuo-ku
Organization Name (eg, company) [Default Company Ltd]:test corp.
Organizational Unit Name (eg, section) []:IT
Common Name (eg, your name or your server's hostname) []:test.com
Email Address []:test@example.com

Please enter the following 'extra' attributes
to be sent with your certificate request
A challenge password []:
An optional company name []:
```

以下の openssl でCSRファイルの中身を確認可能。
- `Subject`
	- 証明書作成要求で入力したサーバー情報
- `Subject Public Key Info`
	- 証明書作成要求の入力に用いた秘密鍵から取り出された公開鍵の情報
- `Signature Algorithm`
	- 例: `sha256WithRSAEncryption`
	- この場合、公開鍵暗号方式に `RSA`, ハッシュ関数に `SHA256` を使用することを示す
- `-----BEGIN CERTIFICATE REQUEST-----` ~ `-----END CERTIFICATE REQUEST-----`
	- PEM形式で記述されたCSRの中身

## 証明書の作成

CSR をもとに証明書の作成依頼を行う。

- 自己証明書
- パブリック証明書

### 自己証明書

自己証明書とは？

サーバー自身の秘密鍵を使用し、サーバーの秘密鍵の正当性であると署名した証明書のこと。

例:
```
// CSRに対して、自身のサーバーの秘密鍵(server.key)を認証に用いる鍵(-signkey)に用いて署名し、証明書(server.crt)の発行を行う
$ openssl x509 -req -signkey server.key < server.csr > server.srt
```

作ってみる
```
$ openssl x509 -req -signkey /etc/httpd/conf/server.key < /etc/httpd/conf/server.csr > /etc/httpd/conf/server.srt
Certificate request self-signature ok
subject=C=JP, ST=Tokyo, L=Chuo-ku, O=test corp., OU=IT, CN=test.com, emailAddress=test@example.com
```

例によって、証明書の内容は openssl コマンドで確認可能
- `Issuer`
	- 認証者
- `Subject`
	- 認証されたサーバー
- `-----BEGIN CERTIFICATE-----` ~ `-----END CERTIFICATE-----`
	- 証明書の本体

### パブリック証明書

認証局により手順は異なるが、基本的には作成した CSR を認証局に送付し、審査を待つ形となる

審査が通ると、認証局から証明書が送られてくる。

証明書は以下のような形なので、サーバー上の秘密鍵を置くディレクトリに証明書ファイルを作成し認証局から送られてきた内容を保存すれば良い。

```
-----BEGIN CERTIFICATE-----
...
-----END CERTIFICATE-----
```

## Apache HTTP 側の SSL設定

httpd + mod_ssl モジュールの使用を全体に、以下のファイルを設定していく

- httpd.conf
- ssl.conf

### httpd.conf

場所: `/etc/httpd/conf/httpd.conf`

- User/Group ディレクティブ
	- サーバーを実行するユーザーとグループを指定
- DocumentRoot ディレクティブ
	- ウェブから見えるメインのドキュメントツリーになるディレクトリ
	- 例: `DocumentRoot /var/www/html`
		- http://www.my.host.com/index.html へのアクセスは `/var/www/html/index.html`が返される
- Listen ディレクティブ
	- サーバーがlistenするIPアドレスとポート番号

### ssl.conf 

- SSLCertificateKeyFile ディレクティブ
	- PEM形式のWEBサーバー秘密鍵ファイルを指定
	- SSLCertificateFile ディレクティブで指定するサーバー証明書にサーバー秘密鍵が含まれている場合は SSLCertificateKeyFIle ディレクティブは不要
		- しかし、サーバー証明書とサーバー秘密鍵は分離することが推奨される
	- 例: `SSLCertificateKeyFile /etc/httpd/conf/server.key`
- SSLCertificateChainFile ディレクティブ
	- PEM形式のチェーン証明書ファイルを指定
	- 下位CAによって署名されたクライアント証明書を認証に使用したい場合、ルートCAからのチェーン証明書が必要
	- 例: `SSLCertificateChainFile /etc/pki/tls/certs/server-chain.crt`
- SSLCertificateFile ディレクティブ
	- Webサーバー証明書を指定する
	- 例: `SSLCertificateFile /etc/httpd/conf/server.crt`

# 簡易版: 自己証明書を用いたHTTPS化

以下を参考に
[チュートリアル: AL2023 に SSL/TLS を設定する - Amazon Linux 2023](https://docs.aws.amazon.com/ja_jp/linux/al2023/ug/SSL-on-amazon-linux-2023.html)

httpdのインストールを行う
```
$ sudo dnf install -y httpd
$ sudo systemctl start httpd && sudo systemctl enable httpd
$ systemctl status httpd
● httpd.service - The Apache HTTP Server
     Loaded: loaded (/usr/lib/systemd/system/httpd.service; disabled; preset: disabled)
     Active: active (running) since Wed 2025-11-12 00:42:56 UTC; 6s ago

...

```

この状態で、外部からアクセス可能となる
```
curl <インスタンスのパブリックIP>:80
<html><body><h1>It works!</h1></body></html>
```

証明書作成のためのパッケージを取得
```
//openssl: SSL/TLS証明書の生成、管理に使用
//mod_ssl: ApacheでSSL/TLSを有効にするために使用

$ sudo dnf install openssl mod_ssl
```

以下のコマンドで自己証明書を作成
```
$ sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 -keyout /etc/pki/tls/private/apache-selfsigned.key -out /etc/pki/tls/certs/apache-selfsigned.crt
```
- オプションについて:
	- req: 証明書署名要求（CSR）または自己署名証明書を作成
	- -x509: 自己署名証明書を作成（CSRではなく）
	- -nodes: 秘密鍵を暗号化しない（パスワード不要）
	- -days 365: 証明書の有効期限を365日に設定
	- -newkey rsa:2048: 2048ビットのRSA秘密鍵を新規作成
	- -keyout: 秘密鍵の保存先
	- -out: 証明書の保存先

つまり、秘密鍵作成 + CSR作成 + 自己署名 + 証明書生成を同時に実行するコマンドとなる

- 秘密鍵
	- `/etc/pki/tls/private/apache-selfsigned.key`
	- 2048ビットRSA秘密鍵が生成される
	- -nodesにより暗号化されていない
- CSR
	- 実際には作成されない
	- -x509オプションにより、CSRを経由せず直接証明書を作成
- 証明書
	- `/etc/pki/tls/certs/apache-selfsigned.crt`
	- X.509形式の証明書が生成される
	- 公開鍵 + メタデータ + 自己署名が含まれる

これにより以下が作成される
- `/etc/httpd/conf.d/ssl.conf`
- `/etc/pki/tls/certs/apache-selfsigned.crt`
